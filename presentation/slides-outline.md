# CCE 2026 — Slides outline

> One block per slide: title, Cengage template layout, what is on the slide, and speaker notes with the image to use (a file in `assets/images/`, a native diagram, or a prompt to generate one). This is the source for `presentation/cce-2026-slides.pptx` (plan-claude.md, steps 15–16). The website carries the detail; the deck is the hook, the map, and the demo cards.

## Design rules

- **One idea per slide, stated as a claim in the title.** The body is one visual and at most three short lines. Everything else goes to speaker notes or the site.
- **No section dividers and no progress strip.** The template's footer band leaves no room for one, so the five-part map lives in the speaker notes of slide 3 and on the Lecture page of the site.
- **Visual hierarchy:** real output from this project first, real VS Code or GitHub screenshots second, native PowerPoint diagrams third, generated illustrations only where the concept cannot yet be shown with a real artifact. The six generated diagrams read well at projector size and are used where noted.
- Image paths are relative to `assets/images/`. Definitions and boxed quotes are verbatim from `docs/content/explanation.md`.
- Layout names are the ones in `presentation/cengage-template.pptx`: Event Title, Session Title, Text with footer, Text with intro text and footer, 1/2/3/4 column with footer, 6 boxes with footer, 3 and 4 column with icons and footer, Image 1, Survey Slide. The template already contains Event Title, Housekeeping, Session Title, Survey, Questions?, and Thank you! slides. The Image 1 layout has a photo background that makes text unreadable, so full-width picture slides use 1 column with footer instead (heading bar as the caption, picture in the body area).
- The deck is generated by `presentation/build-slides.py` (python-pptx). Text goes into the layout's own placeholders, one per column; the only added text boxes are the QR note on slide 1, the question line on slide 3, and the prompt box on slide 7.

## Slide 4 — An agent doesn't answer. It works.

**Layout:** 2 column with footer (image left, text right)

**On slide:**
- > An AI agent uses a model, context, instructions, and tools to work toward a goal through multiple steps.
- **Chat:** you ask → it answers → you do the work
- **Agent:** you give a goal → it inspects → plans → acts → checks
- Boxed: **Chat is the interface. An agent is a way the AI can operate.**

**Speaker notes:**
- Image: `generated/1-what-makes-an-agent.png`.
- Everyone here uses chat already; don't talk it down. The shift is who carries the output and coordinates the steps. On slide 2, nobody copy-pasted.
- What it cannot be assumed to do: know facts it was not given, resolve ambiguity every time, judge what matters pedagogically, replace your review. That sets up slide 14.
- Today the agent runs locally, next to your files, through GitHub Copilot in VS Code. Other places to run one are on the site.

## Slide 14 — Delegate work, not responsibility

**Layout:** 2 column with footer

**On slide:**
- Left, four words: **Protect** sensitive data · **Constrain** what may change · **Verify** the result · **Own** the decision
- Right, **what to try first:**
  1. Open a real project folder in VS Code
  2. Ask Copilot to inspect it
  3. Give it one multi-file task
  4. Create an `AGENTS.md`
  5. Turn one repetitive task into a workflow

**Speaker notes:**
- Image: four native icons (shield, padlock, magnifier, signature). No generated art.
- Protect: sensitive student or research data requires institutionally approved tools, storage, and handling; use synthetic data for experimentation and demonstrations. Everything shown today was synthetic.
- Verify: agents can invent plausible information, misread ambiguous requirements, and make technically valid but undesirable changes. Own: be explicit with students about how AI is used; the grade, the policy, and the decision remain yours.
- Steps 1 and 2 change no files. Start with one folder and one annoying repeated task.
